# HIM OS — User Experience Guidelines

**Version:** 1.5  
**Status:** UX Authority  
**Owner:** Abdulazeez Nurudeen Adedotun  

---

# Purpose

This document defines the user experience philosophy of HIM OS.

Unlike the Design System, which governs visual appearance, this document governs how users think, navigate, interact, and complete tasks throughout the product.

The goal of HIM OS is not to display information.

The goal is to help users make better decisions with less mental effort.

Every workflow, screen, interaction, and navigation pattern should reduce cognitive load and increase clarity.

---

# The HIM UX Philosophy

The interface should disappear.

The user should never think about the software.

They should think only about accomplishing their goals.

Every interaction should feel:

• Calm

• Predictable

• Focused

• Effortless

• Intentional

The software exists to remove friction—not create it.

---

# Executive Operating System Principle

HIM OS is an Executive Operating System.

Executives rarely need every piece of information at once.

Instead they need:

The right information

At the right time

In the right context.

The interface should continuously answer:

"What should I do next?"

---

# One Screen. One Purpose.

Every screen exists to accomplish one primary objective.

Examples

Dashboard

Purpose:
Gain situational awareness.

Today

Purpose:
Execute today's work.

Projects

Purpose:
Advance active projects.

Finance

Purpose:
Understand financial health.

Learning

Purpose:
Continue education.

Review

Purpose:
Reflect and improve.

If a page attempts to solve multiple unrelated problems, it should be redesigned.

---

# The Five-Second Rule

Within five seconds of opening any screen, users should understand:

Where am I?

What am I looking at?

What is most important?

What should I do next?

If these questions cannot be answered immediately, the design has failed.

---

# Progressive Disclosure

Do not show everything.

Show only what the user needs right now.

Advanced functionality should appear only when required.

Example

Wrong

Dashboard displays:

20 metrics

10 charts

15 widgets

Calendar

Finance

Projects

Books

Weather

Habits

Quotes

Goals

Notifications

Correct

Dashboard displays:

Morning Brief

Today's Top 3 Priorities

Focus Session

Quick Progress

Everything else remains one click away.

---

# Information Hierarchy

Every screen should follow the same hierarchy.

Primary

The single most important action.

Secondary

Supporting information.

Tertiary

Historical or reference information.

The user should never need to search for the primary action.

---

# Decision-First Design

HIM OS should support decisions.

Not observation.

Every page should encourage movement.

Examples

Instead of:

"You have 18 tasks."

Present:

"Complete your next priority."

Instead of:

"You've read 32 books."

Present:

"Continue reading Atomic Habits."

Every metric should lead to an action.

---

# Above-the-Fold Strategy

Everything visible without scrolling must be intentional.

Only include:

Page title

Primary action

Current context

Critical metrics

Quick actions

Never place secondary content above the fold.

---

# Navigation Philosophy

Navigation should feel invisible.

Users should never wonder where something lives.

Navigation must be:

Consistent

Predictable

Persistent

Minimal

No page should require more than three interactions to reach.

---

# Sidebar Principles

Maximum of seven primary destinations.

Never nest more than one level.

Icons must be immediately recognizable.

Labels must be short.

Avoid technical terminology.

---

# Command Palette

Ctrl + K is the fastest way to interact with HIM OS.

It should allow users to:

Navigate

Search

Capture

Create

Execute commands

Open recent items

Everything important should be searchable.

---

# Quick Capture Philosophy

Ideas disappear quickly.

Capturing them should take less than five seconds.

Quick Capture must always remain accessible.

It should support:

Tasks

Notes

Expenses

Ideas

Books

Projects

Habits

No unnecessary fields.

Minimal typing.

---

# Cognitive Load

Reduce unnecessary thinking.

Remove decisions.

Remove repetition.

Remove clutter.

The interface should make users feel smarter.

Not busier.

---

# Visual Scanning Pattern

Users naturally scan interfaces.

Priority order:

Top Left

Center

Upper Right

Left Navigation

Remaining Content

Important actions should respect natural scanning behaviour.

---

# Recognition Over Recall

Users should never be expected to remember information.

Show:

Recent items

Suggested actions

Pinned projects

Recently viewed notes

Upcoming reviews

The system remembers.

The user thinks.

---

# Feedback

Every action must produce immediate feedback.

Examples

Button press

Loading

Saving

Success

Failure

Deletion

Undo

Silence creates uncertainty.

---

# Error Handling

Errors should educate.

Never blame the user.

Good example

"Unable to connect.

Check your internet connection and try again."

Bad example

"Unknown Error."

---

# Empty States

Empty pages should never feel empty.

Instead explain:

Why nothing exists.

How to get started.

What happens next.

Include one clear action.

---

# Notifications

Notifications must earn attention.

Never interrupt unnecessarily.

Only notify users about meaningful events.

Examples

Goal completed

Review due

Daily planning reminder

Project milestone

Avoid:

Marketing

Feature announcements

Visual noise

---

# Focus Mode

The Today workspace should support uninterrupted work.

When Focus Mode is active:

Hide navigation

Hide secondary panels

Hide distractions

Increase content spacing

Display only the active task and timer.

---

# Daily Workflow

The ideal daily journey should be:

Morning

↓

Open HIM OS

↓

Read Morning Brief

↓

Review Top 3 Priorities

↓

Start Focus Session

↓

Complete Deep Work

↓

Log Progress

↓

Evening Reflection

↓

Shutdown

Every feature should support this workflow.

---

# Weekly Workflow

Review previous week.

Celebrate wins.

Identify blockers.

Plan next sprint.

Commit priorities.

---

# Monthly Workflow

Reflect.

Measure progress.

Review finances.

Update goals.

Plan the next month.

---

# Search Experience

Search should be universal.

Users should never think:

"Which page contains this?"

Everything should be searchable.

---

# Mobile Experience

The mobile experience is not a smaller desktop.

It is a different experience.

Prioritize:

Capture

Today's work

Habits

Calendar

Quick actions

Deep work timer

Complex analytics belong on desktop.

---

# Performance Perception

Users judge speed emotionally.

The application should always feel responsive.

Use:

Skeleton loaders

Optimistic updates

Instant transitions

Smooth animations

Never leave users wondering if something happened.

---

# Accessibility

Design for everyone.

Keyboard-first navigation.

Large touch targets.

Readable typography.

High contrast.

Reduced motion support.

Accessible forms.

Accessibility is part of good UX—not an optional feature.

---

# UX Review Checklist

Every new screen should answer:

✓ Is the purpose immediately obvious?

✓ Is there one primary action?

✓ Can a new user understand it in five seconds?

✓ Is unnecessary information hidden?

✓ Does every metric lead to an action?

✓ Is the layout visually balanced?

✓ Does the screen reduce cognitive load?

✓ Would an executive enjoy using this every day?

If any answer is "No", redesign the screen before implementation.

---

# Final Principle

Users should never admire the interface.

They should admire what they are able to accomplish because of it.

Great user experience is invisible.

The best compliment HIM OS can receive is:

"I stopped thinking about the software and started thinking about my life."
